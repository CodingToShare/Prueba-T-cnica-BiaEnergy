# PostgreSQL

## Use When

Changing `database/migrations`, `database/queries`, sqlc configuration, indexes, or any query shape.

## Responsibilities

Protect integrity in the database and express data access as explicit, reviewable SQL (ADR-003, `docs/performance/data-query-strategy.md`).

## Required Rules

- Migrations are forward-only goose files, reversible where practical, never edited after being applied in a shared environment.
- Keys, `NOT NULL`, foreign keys, uniqueness (e.g., one reading per meter per timestamp), and check constraints for enumerations and ranges.
- Source observation times are `timestamp without time zone` (ADR-008); system-generated instants are `timestamptz`; half-open time ranges.
- Relational columns for anything filtered, sorted, joined, or aggregated; JSONB only for flexible evidence detail.
- Keep `source_status` and `computed_status` distinct.
- Indexes justified by a named query and checked with `EXPLAIN`.
- Product query SQL lives in `database/queries` and is generated by sqlc (from Phase 03); bulk ingestion uses explicit parameterized pgx statements (TD-18); parameters only.
- No physical-range checks on measurements: unusual values must stay storable for analytics.

## Prohibited

`SELECT *` in application queries; string-built SQL; speculative indexes; JSONB as a substitute for relational modeling; TimescaleDB or other extensions without an ADR.

## Completion Checklist

- Migrations apply from zero on real PostgreSQL in integration tests.
- sqlc generation is up to date (once sqlc is in use).
- Index rationale documented where added.
