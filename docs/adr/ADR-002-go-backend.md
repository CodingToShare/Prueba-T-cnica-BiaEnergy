# ADR-002: Go Backend With Idiomatic Package Boundaries

- Status: Accepted
- Date: 2026-09-24

## Context

The challenge requires Go. The backend must expose a small REST API, persist data in PostgreSQL, run a CPU-bound deterministic analysis, and be easy to test and review.

## Decision

- HTTP routing with a lightweight router (chi) on `net/http`.
- PostgreSQL access through pgx, with type-safe queries generated by sqlc from SQL in `database/queries/` (introduced with the Phase 03 read queries; the Phase 01 bulk ingestion uses explicit parameterized pgx statements, TD-18).
- Schema migrations with goose in `database/migrations/`.
- Structured logging with `log/slog`.
- Layout:

```text
src/backend/
  cmd/api/        HTTP server entry point
  cmd/migrate/    schema migrations (goose as a library, pinned in go.mod)
  cmd/seed/       dataset ingestion entry point
  internal/
    config/       environment configuration        (Phase 01)
    ingestion/    CSV parsing, validation, loading (Phase 01)
    workspace/    locates data/input and database/migrations (Phase 01)
    analysis/     analysis engine, pure (Phase 02)
    analysisrun/  run queue, background worker, result persistence (Phase 03)
    auth/         demo login and signed session cookie (Phase 03)
    httpapi/      /api/v1 router, middleware, validation, DTOs (Phase 03)
    meter/        meter list, detail and reading history (Phase 03; readings live here)
    anomaly/      persisted findings and evidence (Phase 03)
    dashboard/    summary aggregation (Phase 03)
    platform/     postgres (pool, migrations, sqlc code in dbgen), health, jsontime
                  (source vs system time JSON); metrics later
```

- Handlers are thin. Business and analytics rules live in services and the engine.
- Interfaces are declared by the consumer and only at meaningful boundaries: persistence where it improves testability, `ExplanationProvider` (ADR-006), and `Clock` when deterministic time is needed.
- `context.Context` is propagated through all I/O; errors are wrapped and mapped to HTTP centrally.

The package list may be refined when the Go module is bootstrapped (Phase 01); changes that move responsibilities between packages are recorded in the architecture document.

## Consequences

- Small dependency surface, fast builds, a single static binary.
- sqlc makes SQL explicit and reviewable and removes hand-written scanning code; queries must be written as SQL first.
- The analysis engine can be unit-tested with in-memory inputs and no mocks.

## Alternatives Considered

- **ORM (GORM, ent)**: hides query shapes that matter for time-series access and adds magic.
- **Heavier frameworks (Gin, Echo, Fiber)**: acceptable but unnecessary; chi stays on standard `net/http` types.
- **Mechanically ported Domain/Application/Infrastructure projects**: non-idiomatic in Go and adds indirection without value here.
